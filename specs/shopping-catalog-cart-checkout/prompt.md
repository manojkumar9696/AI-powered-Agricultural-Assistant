## Work Items

- **[77600]** Product Catalog Presentation
- **[77613]** As a Shopping website user, I want to open a product detail page so that I can review a purchasable item before selecting it (5 pts)
  Acceptance:
1. A request for a valid product detail route returns a dedicated page populated with productName, sku, category, price, currency, availability, and supporting product details for an active purchasable product.
2. When the same product is visible in the catalog and then opened in the detail view during the active session, the displayed price and availability on the detail page match the currently published catalog data for that product.
3. When the supplied product identifier is malformed, unknown, inactive, deleted, or not purchasable, the system returns a controlled not-found or unavailable state instead of rendering partial product content.
4. The product detail page supports direct URL access, browser refresh, and back-forward navigation while restoring the same product state or the same controlled not-found/unavailable outcome.
5. Product detail requests enforce server-side identifier validation, HTTPS transport, sanitized error responses, and telemetry for successful views, validation failures, not-found/unavailable outcomes, and dependency failures.
- **[77622]** As a Shopping website user, I want to add a product to my shopping cart so that I can select items for purchase (8 pts)
  Acceptance:
1. When a request contains a valid active productId or skuId and an in-stock positive integer quantity, the system adds the item to the current session cart and returns the updated cart item count.
2. If no active cart exists for the current browser session, the first successful add-to-cart request creates a new cart record, associates it to that session, and stores the requested line item in the new cart.
3. If quantity is missing, non-numeric, zero, negative, or greater than available inventory, the system rejects the request with a validation error and does not change any cart or cart item record.
4. If the same add-to-cart request is submitted multiple times with the same request identity key, the system applies only one cart mutation and returns a consistent retry-safe response for subsequent attempts.
5. Each add-to-cart attempt writes an audit entry containing cartId, productId or skuId, requested quantity, timestamp, request identity, and outcome code, excluding payment data and unnecessary personal information.
- **[77631]** As a Shopping website user, I want to review and update my shopping cart so that my selected items remain accurate before purchase (8 pts)
  Acceptance:
1. When the cart page is opened for an active session with an existing cart, the system returns and displays each cart item with product name, quantity, unit price, line total, and the current cart total.
2. When a valid quantity change is submitted for an existing cartItemId owned by the active session and sufficient inventory exists, the system updates that line quantity and recalculates affected totals in the response.
3. When a remove action is submitted for an existing cartItemId owned by the active session, the system deletes that cart line and returns the refreshed cart contents and updated cart total.
4. If a quantity update uses a non-positive or non-integer quantity, references a stale or nonexistent cartItemId, or requests more stock than is available, the system rejects the change and leaves persisted cart contents unchanged.
5. The current cart state for the active session remains available after browser refresh and direct navigation to the cart URL, and each quantity update or removal writes an audit event with cartId, cartItemId, timestamp, old and new quantity where applicable, and outcome code.

- **[77664]** As a shopper, I want to review my cart and begin checkout so that I can confirm my items before purchasing (5 pts)
  Acceptance:
1. The cart review page displays every cart line with product name, unit price, editable quantity, and line subtotal using the current active cart.
2. When a shopper changes a quantity or removes an item, the system recalculates and displays updated subtotal, taxes, discounts, and grand total before any checkout action is allowed.
3. If any cart line is unavailable, exceeds available stock, or contains an invalid quantity, the checkout action is blocked and a cart-level or line-level error message is shown identifying the issue.
4. Selecting the checkout action after successful validation creates a new checkout session or resumes an existing open checkout session for the same cart and redirects to the first checkout step.
5. The cart review page preserves cart state and checkout readiness for both guest and authenticated shoppers using the correct session or account context.
- **[77673]** As a shopper, I want to enter shipping and billing information during checkout so that my order can be fulfilled correctly (5 pts)
  Acceptance:
1. The checkout information step displays editable fields for shipping contact name, email, phone number, shipping address, and billing address required for order processing.
2. When the shopper selects the option to use shipping address as billing address, the system copies the current shipping address values into the billing data model and persists that selection in the active checkout session.
3. The system shows field-level validation errors for missing required fields and rejects invalid email, phone number, or postal code values according to configured validation rules.
4. After a valid submission, shipping and billing information is saved to the active checkout session and repopulates when the page is refreshed or revisited.
5. The Continue to payment action remains blocked until all required checkout information is valid and successfully saved for the active checkout session.
- **[77682]** As a shopper, I want to complete payment securely so that I can place my order with confidence (8 pts)
  Acceptance:
1. The payment step loads the active checkout session and displays the final payable order total together with only the configured supported payment methods.
2. Submitting the payment requires a valid checkout session, a supported payment method selection, and a provider-issued payment token or equivalent secure payment payload.
3. After the shopper selects Place Order, the system blocks duplicate payment submissions for the same checkout session until an authorization result or timeout is received.
4. The system persists and redirects to a newly created order only when the payment provider returns a successful authorization outcome for the submitted payment attempt.
5. If the provider returns a decline, timeout, or processing error, the checkout session remains active, no order is created for that failed attempt, and the shopper sees a retry-capable error message.
- **[77691]** As a shopper, I want to see an order confirmation after purchase so that I know my order was placed successfully (5 pts)
  Acceptance:
1. After successful payment authorization and order creation, the application redirects the shopper to a confirmation route for the completed order.
2. The confirmation page displays the completed order number, purchased items, order totals, and selected shipping details using data retrieved for that orderId.
3. Billing information on the confirmation page is limited to a masked payment reference or summary and never exposes raw payment credentials or sensitive provider data.
4. Refreshing or revisiting the confirmation route reloads the same completed order successfully when the request comes from the authorized session or authenticated order owner.
5. If the orderId is invalid, missing, or not owned by the requesting session or authenticated user, the system returns a safe error page or redirect without exposing order details.
- **[77604]** As a Shopping website user, I want to browse purchasable products in the catalog so that I can discover items available for shopping (5 pts)
  Acceptance:
1. A request to GET /api/catalog/products with valid page and pageSize values returns only products marked active, non-deleted, and purchasable, and each returned item includes productName, sku, price, currency, and availability.
2. When page or pageSize is missing, non-numeric, less than 1, or greater than the configured maximum, the catalog flow returns a controlled client-safe response and no internal exception details are exposed in the UI or API body.
3. When no eligible products exist for the requested page, the catalog page displays a defined empty-state message and renders no incomplete product cards or placeholder price values.
4. When the user navigates between catalog pages, the browser URL updates to the selected page context, and a refresh or back-forward action restores that same page and result set context.
5. Each catalog request is served through HTTPS-protected access, applies rate limiting on the public endpoint, and emits telemetry entries for successful retrieval, empty result, invalid parameter, and downstream failure outcomes.
