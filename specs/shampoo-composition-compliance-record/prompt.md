## User Stories

- **[64951]** As a Regulatory Assessor, I want to classify ABCD Shampoo as a rinse-off cosmetic product so that cosmetic regulatory evaluation uses the correct product type (3 pts)
  Acceptance:
1. When an authenticated Regulatory Assessor saves ABCD Shampoo with productTypeClassification set to "RINSE_OFF_COSMETIC_PRODUCT", the system persists that exact classification on the associated regulatory assessment record.
2. If a user attempts to complete ABCD Shampoo assessment setup while no rinse-off cosmetic product classification is stored, the system rejects the completion action and returns a validation message identifying the missing classification.
3. After a successful save, reopening the same ABCD Shampoo assessment record displays the stored rinse-off cosmetic product classification without requiring re-entry.
4. Each create or update of the rinse-off cosmetic product classification stores audit metadata including acting user and timestamp in the compliance record history.
5. The classification save endpoint rejects unsupported product type values or requests without a valid assessment identifier and does not create a partial record.
- **[64957]** As a Regulatory Assessor, I want to classify ABCD Shampoo as a chemical mixture so that mixture-based regulatory evaluation is supported (3 pts)
  Acceptance:
1. When an authenticated Regulatory Assessor saves ABCD Shampoo with mixtureClassification set to "CHEMICAL_MIXTURE", the system persists that classification on the associated regulatory assessment record.
2. If ABCD Shampoo already has productTypeClassification = "RINSE_OFF_COSMETIC_PRODUCT", saving mixtureClassification = "CHEMICAL_MIXTURE" preserves the existing product type value and stores both classifications on the same record.
3. Retrieving the ABCD Shampoo assessment after a successful mixture classification save returns both the chemical mixture classification and any existing cosmetic product classification in the response payload.
4. Updating the chemical mixture classification does not null, replace, or overwrite unrelated required classification fields already stored for the same assessment.
5. The classification save endpoint rejects requests with unsupported mixture classification values or invalid assessment identifiers and leaves existing classifications unchanged.
- **[64963]** As a Global Compliance Manager, I want to record ABCD Shampoo as a finished consumer product placed on multiple global markets so that market-specific compliance evaluation can be performed (5 pts)
  Acceptance:
1. When ABCD Shampoo is saved with productClassification set to "FINISHED_CONSUMER_PRODUCT", the regulatory assessment record stores that classification and returns it on retrieval.
2. The record allows association of multiple distinct supported market codes in the same assessment record, and the saved response contains each selected market exactly once.
3. If no market is selected during save, the system blocks persistence and returns a validation message identifying target markets as required for market-specific compliance evaluation context.
4. If an unsupported or duplicate market code is submitted, the system rejects the request without partially saving the record or market associations.
5. A user without compliance edit authorization can view the record if permitted by role but cannot create or update the finished-product classification or market selections, and the system returns an authorization error for the write attempt.
- **[64969]** As a Formulation Specialist, I want to define ABCD Shampoo as a formulation composed of multiple raw materials and substances so that compositional assessment can trace all contributing components (5 pts)
  Acceptance:
1. When ABCD Shampoo is saved as a formulation, the product record stores a formulation indicator and persists multiple raw material entries under the same record.
2. Each saved raw material can be linked to one or more constituent substance records, and retrieval returns the same parent-child associations that were submitted.
3. If any raw material in the record has no constituent substance detail, the system prevents final assessment submission and identifies the incomplete raw material entry in the error response or UI.
4. The system rejects write requests containing duplicate raw material identifiers within the same formulation payload or duplicate substance identifiers within the same raw material context, and no partial structure is saved.
5. A user without formulation edit authorization cannot create, update, or delete raw materials or substance links, and the system returns an authorization error for the attempted write.
- **[64975]** As a Regulatory Data Steward, I want to document the complete ingredient list using INCI names so that the finished product record uses the required ingredient naming standard (5 pts)
  Acceptance:
1. The system shall require an INCI name on every ingredient row before the finished product ingredient section can be saved as complete.

3. The system shall persist the full ingredient list with each ingredient's INCI name to the correct single regulatory assessment record for the selected finished product.
4. When an existing finished product record is reopened, the system shall display all previously saved ingredient rows with their stored INCI names exactly as persisted after trimming leading and trailing spaces.
5. Only authenticated users with permission to update regulatory composition data shall be able to create or modify INCI-based ingredient entries; unauthorized update attempts shall be denied without changing stored data.
